# Security Policy

## Supported Versions

Security fixes are currently provided only for the latest 1.0.x release.
Older versions are not supported and will not receive security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

Current version: **v1.0.2**

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

Use GitHub's private vulnerability reporting instead:

1. Go to the **Security** tab of this repository.
2. Click **"Report a vulnerability"**.
3. Fill in the details and submit the report privately.

No dedicated security email is provided. Please use GitHub private reporting.

### What to include in your report

A useful report ideally includes:

- The affected component, file, or version.
- What an attacker can do and under what conditions.
- A minimal reproduction case or proof-of-concept, if available.
- Whether you believe the issue is remotely exploitable.

You do not need a working exploit to report. An incomplete report is better than no report.

### What to expect

This is a volunteer-maintained project. We will do our best to acknowledge and investigate reports in a reasonable timeframe, but cannot commit to strict deadlines. Please give us a fair opportunity to investigate and fix the issue before any public disclosure. If you have not received a response within **90 days**, you may follow up or proceed with disclosure at your discretion.

We will credit reporters in the advisory unless you prefer to remain anonymous.

## Disclosure Policy

We follow coordinated disclosure: please keep vulnerability details private until a fix is released.
